# 活力照片指导：合成场景、多轮核对与双工重放

日期：2026-11-07，Asia/Shanghai。状态：已执行。未修改 prompt。

## 结论

能根据图片提出简短、自然的姿态建议，并接受“改为原地站立”的新意图；**尚不能判定完整指导功能正常**。本轮最明确的失败是：模型要求向画面右边移动，却对向左移到中央的画面也确认“这个位置不错”，没有解释撤销或改变原来的目标。

图文交互和连续音视频分别测试：16 次 chat 请求全部完成；另一次 75 秒合成音视频重放只产生监听事件，没有指导回复。它们均不是真人实时闭环验收。

## 问题与判据

用户只提出“我想拍一张展现活力的照片”，期望模型能观察场景，自然地提出构图、站位、姿势和表情建议；后续根据新画面确认完成或继续纠正。用户中途要求原地站立时，旧的移动目标应被撤回。

不把某个固定构图当成唯一正确答案，也不要求首句一次列完所有动作。重点检查建议是否具体可执行、是否基于实际画面、是否维持当前有效目标，以及是否尊重修改后的意图。到位判断应区分“未动”“方向相反”“遵照建议”，不能只凭赞美用语判断通过。

## 输入与方法

使用内置 imagegen 生成 1536×1024 的草地场景：可见地平线、低角度金色太阳，一位橙色上衣的虚构成年人正面站立。三张编辑图分别表现向左移至中央、略向右移动、保持原位置但挺胸抬头微笑。人工检查画面后使用，图内不写位置或预期答案。

| 图像 | 可观察状态 | 用途 |
|---|---|---|
| 01-initial.png | 人物靠右，约 x=0.76，双臂自然下垂，中性表情 | 初始输入、未动对照 |
| 02-wrong-left.png | 人物约 x=0.50，姿态表情基本不变 | 与“往画面右边移动”相反 |
| 03-requested-right.png | 人物约 x=0.85，姿态表情基本不变 | 遵照“稍往画面右边” |
| 04-standing-smile.png | 原位置，身体舒展，明显微笑 | 接受原地站立后的完成画面 |

坐标为人工估计，不是精确定位标注。编辑图尽量保持背景和身份，纹理不保证逐像素相同。生成目标是朝阳，但单张金色低太阳照片不能可靠区分日出和日落，因此模型说“夕阳”不单独计作识图失败。

### chat 图文与音频对照

每个请求通过 chat 接口创建独立会话，显式提交完整历史文本和历史图片，再追加最新输入。同一对话分叉时复制相同历史；“向左”“向右”“未动”“改主意”分支都从模型已说出向右移动建议的同一历史出发。图片名称和实验判据不发给模型。

设置 streaming=true、max_new_tokens=256、length_penalty=1.0、max_slice_nums=1、omni_mode=false；关闭 TTS、use_tts_template 和 thinking。采样使用 chat 服务默认值，没有宣称与双工配置相同。历史图片增加会拉长完整重算时间，不能将本轮 chat 耗时当作实时帧率。

共 14 次图文/仅图片请求（其中 13 次指导过程、1 次场景描述诊断），另有 1 次图片＋合成语音请求、1 次合成语音转写对照。后两次用于核对双工无回复是否只是音频文件无效，不纳入图文指导通过率。

### video 连续重放

使用正常客户端的 build_session_init、build_video_input、CanvasSource.latest_jpeg(include_character=False) 和 receive_realtime_outputs，通过 video 接口连续运行 75 秒，每秒发送一秒音频和一帧图像。

- 第 3 秒开始播放到输入流的合成语音：“我想拍一张展现活力的照片。”，时长 3.405 秒。
- 第 26 秒开始输入撤回移动要求的合成语音，时长 11.255 秒。
- 第 45 秒将初始图换成原地站立微笑图。
- 第 49 秒开始输入“现在这样可以吗？”，时长 2.355 秒；其余输入音频为静音。
- 使用 Windows Microsoft Huihui Desktop 合成语音，源 WAV 为 16 kHz 单声道 Int16，传输时转为 little-endian Float32 PCM，不发送 WAV 头。三个文件均有非零音量，峰值约 0.55–0.66，RMS 约 0.062–0.065。
- temperature=0.2、top_p=0.8、top_k=10、max_new_speak_tokens_per_chunk=96，generate_audio=false、use_tts=false，force_listen=false，max_slice_nums=1，均沿用正常客户端参数。

这是静态合成图切换配合合成语音的重放，不是连续真实动作录像，也没有真人对建议作出实时反应。

## 双工结果

一次会话成功初始化，发送 75 个 input.append，接收 **75 个 listen 事件、0 个 text、0 个 audio**，正常关闭。该次重放没有任何指导内容，未通过连续指导测试。

音频格式、非零音量、force_listen=false 和 chat 转写已核对。由此可排除“合成文件完全静音”，但不能据此声称双工 ASR 正常，也不能将原因直接归结为提示词。没有修改服务、切换模型或尝试开启语音输出；双工无回复的具体原因仍未定位。

## 可支持的结论与下一轮范围

- 自然建议：可以产生，但初始三次回复的完整程度不稳定；需要追问才能获得相对明确的位置建议。
- 场景与状态：能识别大致背景及位置，不等于能准确判断表情和建议是否完成。
- 连续核对：同一建议下，方向相反和遵照方向都得到位置认可，本轮未通过；主要问题是目标保持与画面对照，而不是缺少更多摄影话术。
- 意图变更：本轮一次对话中，模型接受原地站立，并在后续微笑图确认完成，没有恢复旧的移动要求。尚无多场景或长期稳定性结论。
- 实时链路：本轮双工没有回复；真人实时指导、用户移动中的持续纠正以及方向校准均未验证。

本轮不采用任何新提示词。后续若开展提示词修改，优先只验证“根据最新画面核对当前有效建议是否完成”，保留用户改变目标的覆盖关系；双工无回复单独诊断，避免把传输/生成问题混进图文建议质量比较。
