# 恢复前端与提示词实验基线

> 当天过渡记录，对应 `74b8380`，不是现行约定。其共用动作上下文与指导立绘视图已由 `684d582` 替代；当前行为见 [模式说明](../../docs/modes-and-prompts.md)，维护规则见 [维护协议](../../docs/maintenance/README.md)。下文“当前”仅指该次实验当时。

## 用户确认的目标

共用规则 + 真人拍照指导 / 合照互动两种模式规则，默认指导；由 LLM 理解邀请或恢复指导的话语并请求切换，客户端仅保存当前成功加载的 ON/OFF 记录。模式不作为动作权限，不要求每轮输出动作；后续等待用户指令再开展逐条提示词实验。

## 来源及恢复范围

已通过 GitHub 读取并核对 [AIAA3800 原提示词](https://github.com/DDRP674/AIAA3800/blob/177d70afd6d8e6d95d619621c61117cef8cd59cd/prompt.py) 及同版本前端，使用仓库记录的固定版本，不跟随最新分支。CanvasSource 恢复为该版本实现：白底立绘预览，Q 退出；模型输入仍为相机画面加右上角白底立绘小窗。

ON 不代表角色已经叠加进真人相机画面，不代表已拍摄照片。两种模式使用相同前端与动作分发；move、scale、rotate、tachie 均可执行，保留参数有效性和立绘 ID 检查。保持动画的已有修复、裸文字适配、传输重试及事件日志不回退。

## 修改前后

| 内容 | 修改前 | 当前基线 |
|---|---|---|
| 模板 | 共用 + OFF/ON + 动作诊断 | 共用 + 指导/合照，两种任务模板 |
| 动作 | OFF 阻止全部，ON 只允许 move | 两种模式都解析分发全部已有动作 |
| 回复约束 | ON 每轮 move 或保持；OFF 强化 speak 前缀 | 按用户意图决定说话与动作，仅保留基本标签协议 |
| 模式入口 | photo:enter 单向入画 | mode:co-photo / mode:guidance 双向重建推理会话 |
| 目标询问 | 客户端固定生成 | LLM 根据会话需要决定 |
| 预览 | 相机叠加与 ON/OFF 角标 | 上游白底立绘窗口 |
| ON/OFF 含义 | 动作许可与画面激活 | 最后成功加载的任务提示词 |

新提示词采用上游理想职责与完整动作清单作为基础，按用户要求移除强制动作的措辞，再分离两种任务职责；不是完整回退到旧提交。共用规则含基本标签格式、参数范围、单行连续标签和闭合即可分发。没有保留每轮移动、保持、固定动作顺序、标签逐字前缀强化或示例对话。

## 模式记录与会话

`ModeSelection` 分别保存请求的模式和最后成功加载的模式。启动请求 guidance；收到 session.created 后记录 `session.mode_ready`，`co_photo_active=false`（OFF）。

LLM 输出完整 `<mode:co-photo>` 后，记录 `session.mode_requested`，关闭旧模型会话并组装共用规则 + 合照规则；新会话确认创建后才记录 `co_photo_active=true`（ON）。`<mode:guidance>` 用相同流程返回指导。重复请求当前模式不重建。模式标签与其他标签可以共处一行，跨分块仍需闭合后才解析；切换会终止旧会话尚未完成的生成。

客户端不匹配语音关键词，也不将普通回复中的“和我合照”当作模式指令。是否理解并输出标签是待真人实验验证的模型行为。旧 photo:enter 只保留解析兼容，记录 skipped，不再激活画面。

ON/OFF 可从控制台 `[mode] loaded: OFF (guidance)` / `[mode] loaded: ON (co-photo)` 及本地 JSONL 的 `session.mode_ready` 查看。请求发出不等于加载成功；重建失败保留上次已加载值并记录错误。自定义 `--prompt` / 重放 `--prompt-file` 不启用内置模板切换，模式记录为 custom，布尔值为空。

切换保留相机、麦克风、角色位置、缩放、旋转和立绘；不重载 GPU 权重。旧模型音视频上下文清空，历史目标未结构化继承。编辑 prompt.py 后重启客户端，再按用户安排开始新实验。

## 验证结果

- 71 项本地客户端回归通过。删除旧权限门控用例，替换为两种模式全部动作可执行、无固定询问、双向模式重建及真实解析分发验证。
- 模拟连接验证指导 → 合照 → 指导，旧连接关闭后才新建，非默认角色几何保留；重复请求不重复重建。
- 模拟加载失败验证不会把请求提前记成 ON；自定义覆盖不错误宣称加载内置提示词；用户停止或失败后设备释放。
- 合成图像验证白底立绘和相机小窗布局；单行多个模式/动作标签与分块闭合解析继续通过。
- 对比固定上游导入提交，CanvasSource、compose_model_frame、alpha_composite_at 的 Python 语法树完全一致；两个命令行入口的 --help 与 git diff --check 通过。
- 未打开真人摄像头/麦克风、未做 GPU 推理或新的提示词命中率实验。历史 speak 第一次修改尚未人工验证，本次已撤掉，不算通过。

原始会话和个人设备环境只保留在本地忽略目录。后续每轮只修改用户指定的一项，并追加实际验证结果。
