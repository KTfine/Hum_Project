# 指导模式只保留真人上下文

本轮基于 74b8380，仅处理一个问题：指导模式混入不需要的虚拟角色画面与动作上下文。用户要求把动作提示放到合照模式，并让指导画面不出现虚拟角色。

## 修改前后

| 部分 | 修改前 | 修改后 |
|---|---|---|
| 共用提示词 | 虚拟角色身份、立绘状态与目录、所有动作格式/参数 | 拍照助手身份、语言风格、speak/blank/mode、基本流式格式 |
| 指导提示词 | 继承全部角色动作信息与小窗说明 | 真人指导职责与纯真人画面说明，无角色动作格式、目录和几何状态 |
| 合照提示词 | 共用动作规则 + 合照职责 | 共用规则 + 合照职责 + 独立立绘说明、状态、动作规则 |
| 指导预览/模型输入 | 白底立绘预览 / 相机加立绘小窗 | 相机原图预览 / 相机原图 JPEG；无相机时为空白帧 |
| 合照预览/模型输入 | 白底立绘预览 / 相机加立绘小窗 | 保留 |
| 动作执行 | 不按模式设动作权限 | 保留；即使指导模式产生动作也能更新角色状态 |

例如，相对移动格式和 x/y、scale、rotation、ms 范围从共用规则移到 CO_PHOTO_COMMAND_PROMPT；PHOTO_GUIDANCE_PROMPT 渲染后只含 speak、blank、mode 标签格式。角色的名字和性格可继续共用，避免切换时助手身份突然改变。

画面也必须与职责一致，因此同步修改了客户端与重放工具，而非仅改提示词描述。发送图像采用本会话成功加载的模式快照，避免收到切换请求但还没加载新 prompt 时提前换图；预览同样在会话创建成功后更新。角色数据和设备保持，不重新加载 GPU 权重，旧推理会话上下文仍会清空。

显式自定义 --prompt / --prompt-file 不自动解释任务模式，保持此前带立绘的显示方式。合照仍沿用原小窗结构，未新增角色透明叠加到真人相机画面的功能。

## 验证

- 73 项本地测试通过，git diff --check 通过。
- 指导提示词没有动作标签、立绘目录或几何状态，合照提示词仍含完整动作规则。
- 指导模式编码后的 JPEG 与相同质量参数编码的相机原图逐字节相同，预览不修改相机源图；角色动作仍能执行并保留。
- 无相机时指导预览与模型输入均为空白，无立绘回退。
- 模拟 WebSocket 实际检查指导→合照→指导三次会话发送的 JPEG：不带立绘→带立绘→不带立绘；普通客户端和重放工具均验证。
- 重建失败时保留之前已加载模式和视图；流式多标签和全部动作解析继续通过。
- 未运行本轮 GPU / 真人语音 / 摄像头实验；“减少无关上下文可能改善模型表现”是设计判断，尚无实测质量结论。

后续按用户指定的输入与观察继续实验，不自动加入新的提示词限制。
