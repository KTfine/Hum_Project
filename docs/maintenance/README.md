# 维护协议

生效日：2026-11-07（Asia/Shanghai）。本协议替代此前维护规则、实验流程和待办；用户后续明确要求优先。双模式实现起点为 `684d582`，模型证据从当天记录开始。重建基线不表示删除旧代码，也不表示模型效果已通过。

## 当前产品约定

| 项目 | 约定 |
|---|---|
| 默认任务 | 真人拍照指导，预览和模型图像不含虚拟角色 |
| 指导 prompt | 身份、语言、speak / blank / mode、真人指导职责；无角色动作、立绘目录或几何状态 |
| 合照 prompt | 共用规则 + 合照职责、角色小窗、立绘目录、几何状态及动作格式 |
| 切换 | 模型生成 mode 标签；客户端重建会话，session.created 后才更新视图和就绪状态 |
| 动作 | 模式不做权限门控，保留格式与参数校验；不强制每轮 move / hold |
| 目标询问 | 模型按用户意图决定，客户端不固定插入问句 |
| 输出 | 单行连续标签可跨网络分块，完整闭合即分发 |

细节只在 [模式说明](../modes-and-prompts.md) 和 [接口索引](../reference/README.md) 维护，避免多份文档定义冲突。

## 实验协议

1. 写明本轮问题、变量和判据。用户明确要求多项工程整理时按目的分组，不把“单项实验”误当成需要再次请示的限制。
2. 记录代码 commit、工作区差异、实际发送 system prompt 的 SHA-256、输入类型、接口模式、采样配置及服务版本。只有 prompt.py 哈希不能识别角色参数和自定义覆盖。
3. 分开报告程序回归、纯文本、图文、录音重放和真人实时音视频。每项结论仅适用于实际覆盖的范围。
4. 保存所有尝试，包括连接失败、无回复、漏标签、误切换和被打断。分别统计原生标签、裸文字适配、实际执行和内容正确性，不能用控制台 speak 证明模型原生标签合格。
5. 按 [记录模板](../../experiments/templates/report.md) 新建 `experiments/records/YYYY-MM-DD-主题.md` 并更新 [记录索引](../../experiments/records/README.md)。候选提示词放 experiments/prompts/，可维护实验脚本放 experiments/scripts/，原始日志、媒体和本机脚本放忽略目录 experiments/runtime/；公开仓库只保存必要摘要与可复用实验入口。
6. 新 prompt 重新验证，旧成功率不自动转移。当天撤销方案标记“已替代”，保留真实结果；此前记录不进入新统计、不派生待办、不约束新方案。

[真人评估](../../experiments/plans/human-evaluation.md) 是后续测试设计，不自动写入 prompt，也不是已经得到的模型结论。

## 版本与发布协议

- 提交前检查 status 和 diff，只提交本轮文件；共享工作区有并发修改时重新核对，不整体重置或覆盖他人工作。
- 每个独立目的更新 CHANGELOG，说明行为变化、验证与限制。实验绑定实际 commit；未提交时记录父提交和变更文件，提交后补充定位信息。
- 重置不改写 Git 历史。旧记录从当前目录移除，仍可从旧提交追溯；第三方来源、固定依赖和补丁是复现信息，继续维护。
- prompt 修改检查模板、实际组装和相关模式行为；协议修改检查跨块、多标签、错误输入与执行状态；部署修改检查语法、固定补丁及涉及的运行路径。文档修改检查事实和链接，不为简单改字新增测试。
- 推送前 fetch，确认远端没有冲突；正常推送，不 force push。推送后核对远端 SHA 和该提交 CI，未完成的检查明确报告。
- 不提交凭据、模型权重、本机环境、私人媒体和完整会话。运行文档不把个人账号、机器路径或旧硬件结果当作当前默认条件。
