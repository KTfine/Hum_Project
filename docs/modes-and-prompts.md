# 模式、提示词与执行流程

当前实现对应 2026-11-07 的双模式基线。模式决定加载哪份提示词和显示哪种画面；它不限制合法角色动作的执行。

## 提示词如何组装

[prompt.py](../prompt.py) 保存共用规则和两种模板；[realtime_av_test.py](../realtime_av_test.py) 的 `build_control_prompt` 选择模板并填入会话信息。

| 部分 | 内容 |
|---|---|
| `_COMMON_PROMPT` | 身份、语言风格、speak / blank / mode 指令与流式格式 |
| `PHOTO_GUIDANCE_PROMPT` | 共用规则 + 真人拍照指导职责；默认使用，不含立绘目录、几何状态或动作协议 |
| `CO_PHOTO_COMMAND_PROMPT` | 共用规则 + 合照职责、角色小窗说明、立绘目录、当前几何状态和动作协议 |

组装时填入角色名称、设定、中文回复语言、当前模式的起始上下文和简短麦克风交互说明；合照模板还使用可用立绘 ID 及角色状态。这里的上下文是新会话说明，不是旧对话历史的摘要。修改 prompt.py 后重启本地客户端即可，不需要修改服务或重载 GPU 权重。

## 模式切换

1. 启动时选择 `guidance`，发送对应 system_prompt。
2. 用户说话，模型决定是否生成 `<mode:co-photo>` 或 `<mode:guidance>`。
3. 解析器收到完整标签后，记录 `session.mode_requested`，请求切换。
4. 客户端关闭旧推理会话，使用对应提示词创建新会话。
5. 收到 `session.created` 后，才记录 `session.mode_ready`、更新 ON/OFF 状态并切换画面。

客户端不匹配用户话语中的关键词；只说“已经切换”不会触发模式切换。重复请求当前模式不重建会话，失败也不会提前记录为加载成功。

ON/OFF 只表示最后成功加载的提示词：OFF = guidance，ON = co-photo。尚未成功加载时没有已就绪模式。控制台显示 `[mode] loaded: OFF (guidance)` 或 `[mode] loaded: ON (co-photo)`，本地 JSONL 中也记录模式与 `include_character`。

切换保留设备连接及角色的位置、缩放、旋转状态；旧音视频上下文会重置，未结构化保存的目标不保证继承。它只重建推理会话，不重新加载模型权重。

## 画面与动作

| 模式 | 用户预览 | 模型收到的图像 |
|---|---|---|
| 指导 | 摄像头 | 摄像头，不含立绘 |
| 合照 | 白底立绘窗口 | 摄像头 + 右上角白底立绘小窗 |

指导模式没有相机帧时使用空白帧，不用立绘替代真人画面。合照采用固定上游的立绘布局，不代表透明叠加进真人照片或已经完成拍摄。

两种模式都执行合法的 move、scale、rotate、tachie；客户端只检查格式、数值和立绘 ID。隐藏角色时收到的合法动作仍会改变保留的角色状态。是否说话、移动、保持或询问目标由模型决定，没有每轮强制动作或客户端固定询问。

## 流式标签

支持单行连续标签，例如 `<speak:你好。><tachie:smile>`。每个标签以 `>` 闭合后立即解析、分发，不等待换行或整轮生成结束；标签可以跨网络分块。

标签外普通文字在正常客户端中增量适配为说话，记录 `parser.plain_text_adapted`；不会从这些文字推断动作或模式。判断模型是否原生生成标签，应查看原始输出，不能只看控制台的 speak 结果。未知、非法或不完整标签不猜测执行，TTS 当前关闭。

## 自定义与兼容入口

`--prompt` 或重放工具的 `--prompt-file` 完整覆盖内置提示词，记录为 custom，不自动替换模板，保留原立绘预览和带立绘小窗的模型输入。旧 photo:enter 只保留解析兼容，不再触发入画或切换；旧 action-only 和手动模式启动选项已移除。

`tools/runtime_effect_probe.py` 使用相同模式逻辑，可重放合成语音并记录角色状态；它不是新的提示词模式，也不代表真人实验。使用前查看其 `--help`，历史报告里的旧参数仅用于解释当时的实验。

当前模型效果及限制见 [验证索引](validation/README.md)。
