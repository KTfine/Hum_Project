# 客户端状态同步与精简提示词

## 原架构核对

`CoPhotoSession.active` 决定角色入画和动作权限，程序没有读图识别 ON/OFF，也没有可点击的角标开关。旧 `build_control_prompt` 在连接时写入初始 co_photo_active；收到 photo:enter 后只更新客户端，没有再次发送提示词。旧主提示要求模型依据图片角标判断更新后的状态，所以模型侧存在一次性初始状态与视觉标识两种信息。

## 本次实现

- 共用身份、会话、拍照指导与人的左右规则。正常入口按客户端布尔状态选用 OFF 或 ON 提示词，不将两种状态下的全部规则和未开放动作混在同一份提示里。
- OFF 允许 speak、blank、photo:enter；ON 允许 move、零位移保持与 speak，保留推荐方案、分步指导真人及站到身旁的要求。缩放、旋转和换立绘底层格式未删除，当前权限仍仅移动。单行多标签、闭合即分发和纯文字说话适配保留。
- 以此前已提交模板为基准：旧主提示 2124 字符，新 OFF 685 字符、ON 876 字符。数量是模板字符，不是 token 或延迟测试结果。此前动作专用短提示文字保持不变。
- 用户预览保留状态标识；发送模型的 JPEG 去掉标识，保留真人和角色的相同合成位置。模式状态只由提示词中的客户端信息给出，图像继续用于观察姿势、表情、位置和执行结果。
- 固定上游接口只接受 input.append 与 session.close 等现有消息，未提供提示词热更新。本次在正常入口首次激活后取消旧收发任务，主动关闭旧会话释放 worker，再发送带 ON 的 session.init；没有新增虚构的 session.update 或改动后端服务。
- 同一相机、麦克风、角色控制器和客户端状态贯穿切换，位置及其他几何属性不重置。新会话就绪后由客户端询问一次合照目标，避免用户在重连期间听到询问后作答而丢失开头；TTS 仍关闭，当前询问为文字通道。
- 重放工具同步执行同样的模式更新。重复邀请不会再次建立会话或询问。自定义 --prompt 保持完整覆盖，不擅自改写其内容；动作专用诊断仍显式初始化为已合照。

## 验证

80 项客户端测试通过。新增/更新的验证包括：

- OFF 只包含未入画阶段的指令，ON 保留真人指导且只列开放动作；原有九种格式的解析兼容回归仍通过。
- 两种状态下，用户预览有角标，实际送出的模型 JPEG 没有角标；相机原图不被修改。
- 使用模拟 WebSocket 运行真实解析与分发：旧会话下移动被阻止，photo:enter 激活，旧连接关闭后才建立 ON 会话，新会话移动执行。
- 切换前设置非默认 x/y，检查重连前后不重置；在新连接就绪前不询问，重复邀请不再次刷新或询问。
- 未邀请、用户退出、自定义提示和刷新失败分支；模型会话异常时相机、麦克风得到关闭。
- 两秒固定输入的受控重放也经历 OFF→ON，确认工具确实更新提示并执行后续移动。

本机 18006 当时没有监听；对上一 GPU 的 SSH 端口进行只读连接检查，端口不可用。因此本轮没有 GPU、真人语音或模型生成质量复测，也没有打开本机相机和麦克风。模拟协议测试只验证程序与状态传递，不验证模型会否正确输出或准确推荐站位。此前 46161bb 的动作通过记录属于旧提示/输入条件，不能直接算成本版本模型行为通过。

## 代价与边界

重建推理会话存在一次连接和初始化停顿，本轮未测量实际耗时。旧模型音视频上下文随会话重置，客户端没有独立 ASR 和旧用户音频的结构化记忆，所以不声称完整继承先前拍照目标或左右校准；新会话会询问目标，方向关系不明时需确认。退出合照的触发仍未实现，当前正常运行最多在进入合照时切换一次。

缩短提示词、明确状态和取消角标识别只构成结构改进，不保证模型每次产生动作标签，也没有解决此前人物定位和推荐后执行的全部问题。模型效果与真实端到端重连需在 GPU 服务恢复后另外验收。
