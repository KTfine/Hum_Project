# 拍照指导提示词与真人闭环实验

## 本次结论

用户提供的原始条目式结构可以继续使用。此次沿用角色信息、职责、指令清单和逐条规则，删除演示性输出及示例对话；没有把协议改成 JSON，也没有改动解析器、动作许可或语音播放。

最终模板为 1428 个字符，较此前已提交版本的 1766 个字符减少约 19.1%。用户提供的最初模板为 1138 个字符；增加的内容用于默认真人指导、构图目标持续保持、调整后确认及合照许可。字符数不等同于 token 数或响应延迟。

**真人连续指导未通过。** 当前不能仅凭提示词结构清晰或变短，就认为模型能正确比较目标与实际位置。单独提供视觉观察也没有在本轮消除误判。

## 条件与方法

- 使用现有 MiniCPM-o 4.5 BF16 服务，模型固定版本 `503e754207c94da6bb26850b4469f367c9ea3582`，运行于 RTX 6000D；没有重新安装模型或修改服务代码。
- 真人通过本机摄像头实际移动。测试目标为“我想站在照片最左侧，右边留空。请帮我调整站位”，后两轮只问“现在这样呢？”，不向模型提供预期的移动方向或当前位置答案。
- 窗口允许人工触发或间隔观察，提交最新原始相机帧并按原客户端方式叠加角色小窗。展示文字不画入模型输入。建议使用现有纯文字适配显示，本轮不开麦克风、不播放语音。
- 本轮使用图像与文字的 `mode=chat` 多轮接口，非实时音视频双工验收；三轮画面实际为居中、靠右、更靠近右边缘。用户确认：本人向左移动时，测试预览中的人向右移动。模型输入与测试预览没有额外的左右翻转。
- 对照复用同一组三张真实画面；设置 `max_new_tokens=256`、`length_penalty=1.0`、`max_slice_nums=1`，关闭 TTS 和 thinking。多轮对照发送完整会话；另设去掉历史图像、仅保留历史文字及最新图像的诊断组。
- 所有位置判断均为本轮人工复核，未统计总体准确率。私人画面、完整会话及含本机路径的临时实验程序留在忽略目录，不提交。

## 观察结果

| 实验 | 回复数 | 本轮观察 |
|---|---:|---|
| 真人实际移动，初次条目式候选 | 3 | 前两轮说“向左”，第 3 轮人物靠右时却确认“站位已经合适、右侧留空不错”；未按本人左右明确表达 |
| 用户原始模板，同画面多轮重放 | 3 | 出现全角尖括号的角色移动文字；第 2、3 轮将靠右的人物说成靠左 |
| 条目式修订，同画面多轮重放 | 3 | 第 2、3 轮仍把靠右说成已经到达最左侧 |
| 修订版，仅保留最新图像 | 3 | 去掉历史图像后仍有相同侧别误判，未排除其他历史或目标影响 |
| 中性定位，不给构图目标 | 3 | 对三张图分别回答中间、右侧、右侧；估计脸中心横坐标约 0.48、0.61、0.81，数值未经精度校准 |
| 最右侧目标，使用第 3 张图 | 1 | 仍建议向右移动；此单次结果不用于证明到位判断准确 |
| 最终模板，增加“区分当前位置与目标” | 3 | 没有再次确认到位，但仍连续说向左，未按已确认的预览关系给出自身左右口令 |
| 最终模板，额外传入中性定位结果 | 3 | 第 2、3 轮仍声称人物已经靠左，与传入的当前位置观察矛盾 |

共 22 次回复，其中 3 次中性定位不要求标签；其余 19 次带指令提示的回复均未生成严格解析器可识别的 ASCII 标签。客户端纯文字适配能显示建议，不能修正建议的语义，也没有把这些文字当作角色动作执行。

中性定位与目标指导的差别提示存在目标与当前观察混淆，但不足以定位唯一原因。最终模板的小改动只有本轮固定序列结果，不能据此归因改善或声称问题解决。本次没有获得已满足“最左侧”目标的真人画面，尚未验证正确到位后稳定停止。

## 方向约定与后续范围

自拍不自动代表镜像。提示词不再假定本机一定未镜像，也不展开正面、背面和镜像的通用换算；先确认一次本人移动与预览的对应关系，作为会话信息沿用，朝向或镜像改变后重新确认。当前正常客户端尚未新增校准界面或自动镜像检测，本轮对应关系由用户明确确认并提供给对照实验。

下一步应单独验证可测量的人物位置与构图目标的比较，以及将比较结果转成已校准方向的执行口令；不能仅依赖语言模型说“已到位”。是否采用专用人体检测器或复用模型的独立视觉定位，需要下一步实验决定，本次没有引入检测模型或两阶段生产流程。

最终模板的已有 54 项客户端回归测试通过，覆盖格式渲染、协议解析及输出分发；这些测试不验证视觉判断或摄影指导质量。
