# 合照客户端状态与模型触发验证

## 实现范围

正常客户端每次新建会话从关闭状态开始。角色在右上角小窗；模型识别到明确的同框邀请后，用新增控制请求 `<photo:enter>` 申请进入合照。客户端确认有可用相机帧才激活自己的状态，将透明立绘叠加到真人取景画面，并开放 move；scale、rotate、tachie 继续阻止。

首次激活时，客户端直接向现有说话通道提交“你想一起拍什么样的照片？可以告诉我要求，也可以让我推荐一个。”，保证该询问不依赖模型补发 speak。重复邀请不再次询问，不重置位置或几何属性。当前说话通道显示文字，TTS 仍关闭。

原九种格式保留，新增一种控制请求；单行连续标签、跨块缓存和完整标签闭合后立即分发均保留。激活前的移动不会因同一批后面有入画请求而补执行，激活后的移动才放行。无相机、相机无新帧、非法控制参数及未闭合标签都不能完成入画。

预览与模型输入共用 render_scene：关闭时是相机加角色小窗；开启后按相机实际尺寸、透明度和现有几何状态合成，不把角色的白色画布盖到真人画面上。左上角 CO-PHOTO: OFF/ON 是客户端状态反馈；初始状态也写入模型会话信息。

提示词保留默认真人拍照职责，在同一个文件中加入合照流程：激活后等待目标；用户授权推荐则提出简单方案，直接给要求则按要求进行；分步指导真人站位、姿势和表情，角色当前仅通过移动测试站在身旁。没有新增姿势动画、自动跟踪、退出口令或拍照保存。

## 本地检查

客户端共 66 项测试通过，其中新增 12 项覆盖默认权限、标签顺序、入画与移动跨网络分块、客户端首次询问、重复邀请幂等、无相机拒绝、初始状态反馈及透明合成。旧视频输入测试只调整了像素检查区域，避开新增的状态标识。

这些测试验证程序行为，不能证明模型理解每种邀请、推荐质量或人物视觉定位可靠。激活请求的语义仍由当前模型判断，没有新增独立 ASR 或确定性邀请分类器。

## GPU 实验

使用现有 RTX 6000D 上的 MiniCPM-o 4.5 BF16，固定模型版本 `503e754207c94da6bb26850b4469f367c9ea3582`。复用此前授权采集的同一私人相机帧，不打开本次麦克风或摄像头；音频测试使用 Windows 中文合成语音，通过实际实时音视频网关发送。私人帧、合成图、完整会话和本机实验程序不提交。

| 检查 | 本轮结果 |
|---|---|
| 最终提示词，图像文字：先拒绝合照，再明确邀请 | 先保持关闭，邀请时生成 photo:enter，客户端真实激活并发出目标询问 |
| 同一图像文字会话，要求角色向左，再移到横向四分之三 | 生成 move 标签，实际 x 从 0.5 到 0.45，再到 0.75，预览合成同步变化 |
| 同会话要求缩小 | 生成非法 scale 格式，解析器丢弃，没有缩小；合法但未开放的动作由新增单元测试验证阻止 |
| 重复邀请 | 保留当前位置，客户端没有重复激活或询问 |
| 早期图像文字候选的普通指导、假设、引用及否定控制组 | 本轮均保持关闭；不据此声称所有误触发已经排除 |
| 初次 102 秒音频重放 | 模型只口头答应，未生成激活标签，状态保持关闭，记录为失败 |
| 将触发约束提前的 22 秒音频对照 | 仍只口头答应，未激活；未保留该重复约束 |
| 最终流程的 34 秒音频重放 | 邀请产生激活标签，客户端入画并询问目标；后续左移只产生普通文字，未执行移动 |
| 初始化为开启状态的 32 秒音频诊断 | 左移和绝对站位要求仍只产生普通文字，未执行移动；说明只改变初始状态未消除格式问题 |
| 最终提示词，图像文字：邀请后说“你推荐一个”，再直接给自然合照要求 | 激活与首次询问通过；后续产生方案文字和站好位置的口头表述，没有 move，位置保持 x=0.5，站在身旁未通过 |

在最终推荐流程前也出现过候选询问方案但漏发入画请求，及推荐仅口头答应的失败。后续明确了邀请语义和初始客户端状态，不能以先前一次移动成功替代最终推荐流程验收。

结论：客户端入画、权限、询问和渲染已经实现；真实模型的显式图文邀请与直接移动请求有通过记录，真实音频也有一次激活记录。语音移动及“推荐后实际站到人身旁”的闭环仍未通过，不以口头承诺或单次成功宣称稳定可用。真人姿势、表情指导质量和长期稳定性仍待独立验证。

## 重放入口

新增独立的 co-photo 合成语音配置和时间线，旧动作回归工具默认行为保留。以下命令会使用本机相机，但用固定合成语音代替麦克风；需先建立现有 SSH 隧道，确保没有其他客户端占用模型 worker。

```powershell
.\scripts\generate_action_probe_speech.ps1 -Profile co-photo -Voice 'Microsoft Kangkang'
.\.venv-client\Scripts\python.exe tools/runtime_effect_probe.py --co-photo --seconds 102 --instructions-file tools/fixtures/co-photo-schedule.json --output-subdir co-photo-replay
```

`--co-photo` 让测试采用与正常客户端相同的动态权限。结果的状态时间线含 co_photo_active，记录激活和各次实际应用或阻止的指令，保存本机合成预览。该入口用于复查通过与失败，不保证每次模型输出相同，也不将纯文字承诺判成动作成功。
