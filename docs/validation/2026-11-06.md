# 2026-11-06 动作修复验证

## 问题及修复

原模型理解中文要求，但返回普通文字，没有 `<move:...>` 等标签。检查实际会话记录与模型初始化 usage 后，确认原提示词已进入后端；原提示词改用 greedy 仍没有动作。将控制任务集中表述、加入明确示例后，原采样设置下可以输出并执行动作。

客户端动作执行代码沿用原版。模型权重、解析器和执行器没有为这些用例硬编码动作；测试工具只发送输入及读取状态。另修复了后端会话设置只写入配置对象、未到达实际生成器的问题，使禁用语音和 token 上限生效。

## 复测方法

在 Windows 安装客户端依赖并连接 SSH 隧道后，用已安装的 System.Speech 中文音色生成本地测试语音：

```powershell
.\scripts\generate_action_probe_speech.ps1 -Voice 'Microsoft Huihui Desktop' -Profile baseline
.\scripts\generate_action_probe_speech.ps1 -Voice 'Microsoft Kangkang' -Profile generalization
.\scripts\generate_action_probe_speech.ps1 -Voice 'Microsoft Yaoyao' -Profile generalization -OutputSubdir action-voice2
.\.venv-client\Scripts\python.exe tools/runtime_effect_probe.py --seconds 42 --output-subdir regression
.\.venv-client\Scripts\python.exe tools/validate_action_probe.py runtime_results/regression --profile baseline
.\.venv-client\Scripts\python.exe tools/runtime_effect_probe.py --seconds 128 --instructions-file tools/fixtures/action-generalization-schedule.json --output-subdir generalization
.\.venv-client\Scripts\python.exe tools/validate_action_probe.py runtime_results/generalization
```

第二种音色使用 `tools/fixtures/action-generalization-voice2-schedule.json`。可添加 `--preview` 观察角色窗口。测试自动停止并释放摄像头，结果写入已忽略的 `runtime_results/`。语音合成结果随本机语音引擎版本变化，不保证与本轮 WAV 文件逐字节一致。

后端方法回归不需要 GPU，但需要已应用补丁的固定 Demo 源码：

```bash
export MINICPM_UPSTREAM_DIR=/absolute/path/to/upstream
python -m unittest discover -s backend/tests -p test_duplex_session_options.py -v
```

## 后续：真实音视频输入的 60 秒验证

在恢复默认真人指导提示词后，使用真实麦克风与摄像头运行原客户端 60 秒，发送 58 个一秒音视频块，未记录网关错误；采集到声音，模型返回与站位目标相关的自然语言。测试没有开启合照或语音播放，结束后摄像头和麦克风均释放，服务恢复空闲。

模型回复没有 speak 标签，因此原解析器产生 0 条说话指令，角色动作也为 0。结论是输入和回复链路可用，实时输出协议未通过；不能据此宣称拍照指导闭环完成，也尚不能判定模型是否正确验证了真人调整后的站位。该测试与此前带文字问题的单帧图像测试属于不同调用模式。

复核当前和历史原始事件后，中文文本保存正常，没有出现替换字符；本地诊断 Python 的默认 stdout 为 GBK，未统一输出编码时工具展示出现乱码。撤回此前将该显示现象视为模型中文生成缺陷的判断，标签缺失问题仍然成立。原始采集内容及完整会话记录不提交到仓库。
