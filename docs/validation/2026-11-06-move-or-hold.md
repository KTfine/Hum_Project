# 动作或保持：提示词与实际执行实验

## 本次改动

- 主提示词要求合照 ON 的每次有效回复先输出 move，保持原地也必须给出明确的零位移指令；观察、问答或只指导真人时要求保持并用 speak 回答，用户要求角色移动或授权的合照方案需要移动时才改变位置。未合照的权限与静默监听行为保持。
- 沿用现有格式：保持为 `<move:by,dx=0,dy=0,ms=0>`。它是保持/停止指令，不是视觉上的闲置动画，也不等于移动到拍摄目标位置。没有添加示例对话或演示性输出。
- 修正零位移的一个执行边界：此前相对移动累加于动画的旧目标，ms=0 的零位移可能立即跳到该目标。现在零时长、全零位移冻结所指定轴的当前插值位置，其他轴及缩放、旋转动画独立继续。非零相对移动仍按原来的目标累加规则处理。
- 新增短提示词 CO_PHOTO_ACTION_DIAGNOSTIC_PROMPT 和显式实验入口。正常拍照助手仍使用完整主提示词，动作专用提示只在诊断时选用；没有把普通文本推断成动作，也没有在客户端补出动作来代替模型生成。

## 条件与评价方法

使用现有 RTX 6000D 上的 MiniCPM-o 4.5 BF16，模型版本 `503e754207c94da6bb26850b4469f367c9ea3582`，没有改模型、上游解码器或部署环境。固定输入测试复用授权的私人相机帧和同一 Windows 中文合成语音，走实际实时音视频网关；进入测试时显式初始化为已合照，以隔离激活与动作生成问题。

三条固定口令依次为角色左移、保持原地、推荐合照并站到真人身旁，分别在第 3、20、36 秒发送。含观察的额外诊断在第 52 秒询问可见表情。所有组使用相同基础帧、语音、生成配置和初始 x=0.5；实际角色反馈随各组输出变化。单次小样本结果不构成总体准确率或因果归因。

分别检查模型原始标签、解析与实际应用记录、角色坐标和合成画面。零位移只计保持，非零位移也不自动等于已经站到真人身旁。检查固定版本的双工采样入口确认：当前未接入本项目动作标签的解码语法约束，因此提示词中的“必须”仍需逐项验证，不能当作程序级输出保证。

## 图像文字对照

旧主提示在左移、保持、推荐、表情观察四轮中生成两条 move。强制动作初稿生成四条 move，但在只问表情时额外移动并省略回答，该候选存在语义问题。

补充“问答保持并回答”后，最终主提示生成三条 move：左移实际执行，保持指令正确，推荐产生非零位移；表情观察回到普通文字并保持位置，但漏了要求的零位移标签。此结果仍未满足每次有效回复都有 move 的完整要求，也未验证推荐位置真正合适。图像文字结果不替代音频结果。

## 真人语音测试

经用户确认当前方便后，实际打开本机相机和麦克风运行纯动作诊断 60 秒；初始合照状态显式设为开启，TTS 关闭。发送 58 个音视频块，有实际声音输入。模型输出三条完整的左移标签，均进入执行器，x 为 0.5→0.4→0.3→0.2。用户确认主要要求向左，执行基本正确。

计时结束时另有一段未闭合的标签，没有作为动作执行。由于未保存真人逐字转写及完整口令清单，不报告真人识别命中率；本次没有验收真人的保持、向右或推荐站位。结束后相机、麦克风和窗口已释放。

私人图像、合成预览、原始会话及临时测试程序不提交。

## 复测与限制

真人入口：

```powershell
.\.venv-client\Scripts\python.exe realtime_av_test.py --url https://localhost:18006 --insecure --action-only-test
```

该入口需要相机，明确跳过邀请流程并初始化为已合照；只接受动作测试，不提供摄影聊天，不能同时用 --prompt 覆盖。按 Q 退出。默认产品入口仍保留真人拍照与伙伴对话职责，没有自动切换到纯动作提示。

固定合成语音入口：

```powershell
.\scripts\generate_action_probe_speech.ps1 -Profile co-photo -Voice 'Microsoft Kangkang'
.\.venv-client\Scripts\python.exe tools/runtime_effect_probe.py --co-photo --start-co-photo --action-only --seconds 58 --instructions-file tools/fixtures/co-photo-action-required-schedule.json --output-subdir action-only
```

71 项客户端回归通过，新增检查覆盖动画中停止、单轴保持不影响其他动画、诊断提示显式选择与激活条件，以及真人诊断参数约束。完整模型的逐回复动作保证、推荐后真正站在身旁、混合对话及动作的可靠执行仍未完成，需继续研究规划与动作输出如何隔离或约束。
