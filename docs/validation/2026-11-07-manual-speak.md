# 人工提示词实验：第一轮 speak 标签

## 范围与基线

基线代码为 bc57aad。本轮只验证普通 OFF 模式的原始 speak 标签输出，由用户手动说话与观察。用户提供的已有结果：文字回复和语音识图通过；普通提示仍会输出裸文字，邀请未生成 photo:enter；纯动作诊断生成过左移与保持，角色 x 从 0.5 到 0.4。这些属于历史结果，不计入本轮命中率。

## 唯一提示词修改

将 STREAMING_COMMAND_PROMPT 的“其他情况用 speak”细化为可直接执行的输出顺序。假设：明确标签前缀与闭合字符，可能减少模型直接开始自然语言回复的情况；效果待真人测试。

```diff
- 其他情况用 speak；无须回复用 blank。请求你移动时先确认合照意图，当前不输出移动。
+ 其他情况需要回答时，先输出字面前缀 <speak:，再输出说话内容，最后用 > 闭合；所有说话内容都在标签内。无须回复用 blank。请求你移动时先确认合照意图，当前不输出移动。
```

共用规则、ON 提示词、动作诊断提示词、采样参数和客户端代码均保持原样。保留单行连续多个标签、完整闭合即可分发、跨网络分块解析和普通文字适配。没有添加示例对话。

## 测试条件与判定

- 测试前已核对 SSH 转发连接到本次指定服务器；网关 health 返回 HTTP 200，status 返回 HTTP 200、gateway_healthy=true、1 个空闲 worker、队列长度 0。此检查不等同于 GPU 推理质量验证，也未独立核对远端物理 GPU 编号。
- 使用本仓库 realtime_av_test.py 的正常入口、新会话、默认采样配置、合照 OFF。不使用 action-only-test 或自定义 prompt。修改后必须重启客户端。
- 用户先后说“你好，介绍一下你自己。”“你叫什么名字？”“你能帮我做什么？”“请用一句话描述你现在看到的画面。”“请把刚才的描述再简短一点。”每次等回复结束再继续，不在话语中提醒标签格式。本轮不发合照邀请或移动口令。
- 每轮从 gateway.receive 的 response.output.delta / kind=text 中，按 response_id 和到达顺序拼接原始文本。网络分块可拆开标签，不能把每个分块当作一轮。
- 单条原始回复至少包含一个完整、非空的 speak 标签，且没有标签外文字或未闭合标签，才算该条格式通过；连续多个 speak 标签同样有效。另核对解析器分发记录，检查内容是否实际显示。
- 控制台 [speak] 和 parser.command 本身不能证明模型生成了标签；普通文字适配也会产生这些结果。parser.plain_text_adapted 应单独统计并结合原始文本判断。
- 记录 5 个输入各自的回复/无回复情况、完整标签回复数、裸文字/混合文字回复数、未闭合回复数及适配次数。若输入被漏听、打断或产生多个回复，单独标记，不静默丢弃。无回复不能计为标签通过。
- 5/5 仅记为“本轮短测通过”，不宣称长期稳定。内容正确性另记，不把 speak 格式通过当作真人构图指导或合照闭环通过。
